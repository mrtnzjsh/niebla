Niebla compiles into four self-contained Go binaries with zero external runtime dependencies:
* `niebla` — Developer CLI for managing workspaces, inspecting diffs, shelving CLs, and submitting to [trunk](https://en.wikipedia.org/wiki/Trunk-based_development).
* `nieblafs` — [FUSE](https://en.wikipedia.org/wiki/Filesystem_in_Userspace) virtual filesystem daemon for Linux workstations.
* `niebla-server` — Central [gRPC](https://en.wikipedia.org/wiki/GRPC) repository server and [CAS](https://en.wikipedia.org/wiki/Content-addressable_storage) coordinator.
* `cotejo` — Web code review server.

Select your platform below to install Niebla `v0.1.0`:

<Tabs>
  <TabItem label="NixOS & Home Manager">
    On NixOS, the repository flake provides a declarative system module (`services.niebla`) that provisions `niebla-server`, `cotejo`, and an isolated PostgreSQL instance automatically.

    #### 1. Add the Flake Input
    Add `niebla` to your `flake.nix`:

    ```nix
    inputs.niebla = {
      url = "github:mrtnzjsh/niebla";
      inputs.nixpkgs.follows = "nixpkgs";
    };
    ```

    #### 2. Enable the NixOS Service (Server + Client)
    ```nix
    imports = [ inputs.niebla.nixosModules.default ];

    services.niebla = {
      enable = true;
      postgres.enable = true; # Isolated PostgreSQL instance on port 5433
      server.enable = true;   # Repository gRPC daemon on port 50051
      cotejo.enable = true;   # Code review web UI on port 8080
      client.enable = true;   # Installs niebla & nieblafs in system PATH
      fuse.enable = true;     # Automatically configures programs.fuse (enable = true & userAllowOther = true)
    };
    ```

    :::note[Automated FUSE Security Wrappers]
    On NixOS, mounting virtual workspaces requires the setuid wrapper (`/run/wrappers/bin/fusermount3`) and `/etc/fuse.conf`. When `services.niebla.enable = true`, `services.niebla.fuse.enable` defaults to `true`, automatically managing `programs.fuse.enable = true` and `programs.fuse.userAllowOther = true`. For headless server-only deployments without FUSE, set `services.niebla.fuse.enable = false;`.
    :::

    Apply the configuration:
    ```bash
    sudo nixos-rebuild switch --flake .
    ```

    #### Client-Only Home Manager Module (Linux / nix-darwin)
    If you only need the `niebla` client and AI agent skills on a workstation:

    ```nix
    imports = [ inputs.niebla.homeManagerModules.default ];

    programs.niebla = {
      enable = true;
      enableSkills = true;
    };
    ```
  </TabItem>

  <TabItem label="Linux (Pre-built Release)">
    Pre-compiled release archives are available for Linux (`amd64` and `arm64`).

    #### 1. Download & Verify the Archive
    ```bash
    VERSION="v0.1.0"
    ARCH="amd64" # "amd64" or "arm64"

    curl -sSL -O "https://github.com/mrtnzjsh/niebla/releases/download/${VERSION}/niebla_${VERSION}_linux_${ARCH}.tar.gz"
    curl -sSL -O "https://github.com/mrtnzjsh/niebla/releases/download/${VERSION}/checksums.txt"

    sha256sum --check --ignore-missing checksums.txt
    ```

    #### 2. Install Binaries to `PATH`
    ```bash
    tar -xzf "niebla_${VERSION}_linux_${ARCH}.tar.gz"
    sudo install -m 755 niebla nieblafs niebla-server cotejo /usr/local/bin/
    ```

    For a non-root install, copy the binaries to `~/.local/bin/` instead.

    #### 3. Enable Non-Root FUSE Mounts
    Ensure `/etc/fuse.conf` allows unprivileged mounts:
    ```bash
    sudo usermod -aG fuse "$USER" 2>/dev/null || true
    sudo sed -i 's/#user_allow_other/user_allow_other/' /etc/fuse.conf || echo "user_allow_other" | sudo tee -a /etc/fuse.conf
    ```
  </TabItem>

  <TabItem label="Linux (Build from Source)">
    Building from source requires Go 1.26+ and `fuse3` for virtual workspace mounts.

    #### 1. Install Dependencies
    * **Debian / Ubuntu:**
      ```bash
      sudo apt update && sudo apt install -y git make golang-go fuse3 libfuse3-dev pkg-config
      ```
    * **Fedora / RHEL:**
      ```bash
      sudo dnf install -y git make golang fuse3 fuse3-devel pkgconf-pkg-config
      ```
    * **Arch Linux:**
      ```bash
      sudo pacman -S --needed git make go fuse3 pkgconf
      ```
    * **Alpine Linux:**
      ```bash
      apk add git make go fuse3-dev build-base
      ```

    #### 2. Clone & Build
    ```bash
    git clone https://github.com/mrtnzjsh/niebla.git
    cd niebla
    CGO_ENABLED=0 go build -o bin/niebla ./cmd/niebla
    CGO_ENABLED=0 go build -o bin/nieblafs ./cmd/nieblafs
    CGO_ENABLED=0 go build -o bin/niebla-server ./cmd/niebla-server
    CGO_ENABLED=0 go build -o bin/cotejo ./cmd/cotejo

    sudo install -m 755 bin/niebla bin/nieblafs bin/niebla-server bin/cotejo /usr/local/bin/
    ```

    #### 3. Enable Non-Root FUSE Mounts
    Ensure `/etc/fuse.conf` allows user mounts:
    ```bash
    sudo usermod -aG fuse "$USER" 2>/dev/null || true
    sudo sed -i 's/#user_allow_other/user_allow_other/' /etc/fuse.conf || echo "user_allow_other" | sudo tee -a /etc/fuse.conf
    ```
  </TabItem>

  <TabItem label="macOS (Darwin)">
    macOS workstations run the `niebla` CLI in [Direct Materialization Mode (`--no-fuse`)](/niebla/workflows/direct-materialization/), which requires no kernel extensions (`macFUSE` is not needed).

    #### Option A: Pre-built Release Binary
    ```bash
    VERSION="v0.1.0"
    ARCH="arm64" # "arm64" (Apple Silicon) or "amd64" (Intel)

    curl -sSL -O "https://github.com/mrtnzjsh/niebla/releases/download/${VERSION}/niebla_${VERSION}_darwin_${ARCH}.tar.gz"
    tar -xzf "niebla_${VERSION}_darwin_${ARCH}.tar.gz"
    sudo install -m 755 niebla /usr/local/bin/
    ```

    #### Option B: Build from Source
    ```bash
    brew install go git
    git clone https://github.com/mrtnzjsh/niebla.git
    cd niebla
    CGO_ENABLED=0 go build -o /usr/local/bin/niebla ./cmd/niebla
    ```

    #### Configure Default `--no-fuse` Mode
    Export `NIEBLA_NO_FUSE=true` in `~/.zshrc` (or pass `--no-fuse` when creating workspaces) and point `[core]` in `~/.config/niebla/config.toml` to your server:
    ```toml
    version = 1

    [core]
    server_addr = "127.0.0.1:50051" # Or your remote server address
    ```
  </TabItem>
</Tabs>
